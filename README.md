# Media File Scanner Suite

Набор утилит на C++20 для сканирования медиафайлов (аудио, видео, изображения) в домашней директории пользователя. Проект состоит из трех компонентов: автономного сканера, сканера-сервера с REST API и клиента для взаимодействия с сервером.

## Особенности

-   **Три исполняемых файла**:
    - `scaner`: Автономное консольное приложение, которое периодически сканирует файлы и сохраняет результат в JSON-файл.
    - `scaner_server`: Демон-сервер, который выполняет сканирование и предоставляет результаты по HTTP.
    - `scaner_client`: Клиент для запроса данных у `scaner_server`.
-   **Гибкое сканирование**: Поддержка рекурсивного и нерекурсивного обхода каталогов.
-   **Формат путей**: Возможность вывода как абсолютных, так и относительных путей к файлам.
-   **Периодический запуск**: Встроенный таймер на базе `timerfd` для регулярного повторного сканирования с настраиваемым интервалом.
-   **Современный C++**: Проект написан на C++20 с использованием `std::filesystem`, `std::optional` и других современных возможностей.
-   **Кросс-платформенная сборка**: Используется CMake для сборки проекта.
-   **Поддержка санитайзеров**: Встроенная конфигурация для легкой сборки с AddressSanitizer (ошибки памяти), UndefinedBehaviorSanitizer (неопределенное поведение) и ThreadSanitizer (гонки данных) для всесторонней отладки.

## Компоненты

### 1. `scaner`

Консольная утилита, которая работает в фоновом режиме. Она периодически сканирует домашнюю директорию на наличие медиафайлов и сохраняет список найденных файлов в файл `~/.media_files` в формате JSON.

**Основное применение**: Локальный сбор информации без необходимости сетевого взаимодействия.

### 2. `scaner_server`

Легковесный HTTP-сервер, который выполняет ту же логику сканирования, что и `scaner`. Однако вместо сохранения в файл, он предоставляет результаты по запросу на эндпоинт `/media_files`.

-   **Адрес**: `localhost`
-   **Порт**: `1234`
-   **Эндпоинт**: `GET /media_files`
-   **Ответ**: JSON-объект с тремя ключами: `audio`, `video`, `images`, содержащими списки файлов.

**Основное применение**: Предоставление данных о файловой системе другим приложениям через простой и универсальный API.

### 3. `scaner_client`

Простой клиент командной строки для тестирования `scaner_server`. Он отправляет GET-запрос на `/media_files` и выводит полученный JSON в консоль.

### `scaner.h` - Модуль сканирования

Это ключевой заголовочный файл, содержащий всю основную логику для обнаружения и каталогизации медиафайлов. Он спроектирован так, чтобы быть переиспользуемым как для автономного сканера, так и для серверного приложения, что устраняет дублирование кода.

#### Основные компоненты:

-   **Структура `Filter`**
    -   Содержит три `std::unordered_set<std::string>` для быстрого определения принадлежности файла к одной из категорий: `audio`, `video` или `images`.
    -   Метод `Check(const std::string& extension)` эффективно проверяет расширение файла и возвращает `std::optional<std::string>` с именем категории или `std::nullopt`, если тип файла не поддерживается.

-   **Функция `ProcessDirectory<DirectoryIterator>`**
    -   Шаблонная функция, которая абстрагирует логику итерации по директории. Она может работать как с `std::filesystem::directory_iterator` (для нерекурсивного обхода), так и с `std::filesystem::recursive_directory_iterator` (для рекурсивного).
    -   Обрабатывает ошибки доступа к файлам и директориям, используя флаг `fs::directory_options::skip_permission_denied`.
    -   Приводит расширения файлов к нижнему регистру для регистронезависимого сравнения.

-   **Функция `ListFiles`**
    -   Точка входа для запуска процесса сканирования. Принимает путь, объект `Filter` и флаги для рекурсивного обхода и формата путей.
    -   Возвращает `std::unordered_map<std::string, std::vector<std::string>>`, где ключами являются категории ("audio", "video", "images"), а значениями — списки найденных файлов.

-   **Функция `GetHomeDirectory`**
    -   Кросс-платформенно-безопасный (в рамках POSIX-систем) способ получения домашней директории текущего пользователя. Сначала пытается прочитать переменную окружения `HOME`, а в случае неудачи использует системный вызов `getpwuid(getuid())`.

-   **Структура `AppOptions` и функция `GetArguments`**
    -   Предоставляют удобный интерфейс для парсинга аргументов командной строки. `GetArguments` разбирает флаги, такие как `-t` (время), `-r` (рекурсия) и т.д., и возвращает структуру `AppOptions` с заполненными параметрами и кодом завершения. Это делает код в `main()` более чистым и читаемым.

### `linux_timer.h` - Периодический таймер

Этот модуль предоставляет простую в использовании функцию для выполнения повторяющихся задач через заданный интервал времени. Он основан на специфичном для Linux API `timerfd`, который является эффективным и надежным способом работы с таймерами на уровне ядра.

#### Основные компоненты и принцип работы:

-   **Сигнальный обработчик `SignalHandler`**
    -   Перехватывает сигналы завершения программы (`SIGINT` (Ctrl+C), `SIGTERM`, `SIGTSTP` (Ctrl+Z)) и устанавливает глобальный атомарный флаг `running` в `false`. Это обеспечивает "graceful shutdown" (плавное завершение) приложения.
    -   Для регистрации обработчика используется `sigaction`.

-   **Функция `TimerStart<Functor>`**
    -   Принимает в качестве аргументов лямбда-функцию (или любой другой вызываемый объект) и задержку в секундах.
    -   **Создание таймера**: `timerfd_create(CLOCK_MONOTONIC, 0)` создает файловый дескриптор таймера. `CLOCK_MONOTONIC` гарантирует, что таймер не будет затронут изменениями системного времени.
    -   **Настройка интервала**: `timerfd_settime` настраивает первую задержку (по умолчанию 2 секунды) и последующий интервал срабатывания.
    -   **Цикл ожидания**:
        -   Основной цикл `while(running)` ждет событий с помощью `poll()`. `poll` блокирует выполнение до тех пор, пока файловый дескриптор таймера не станет доступен для чтения, что означает срабатывание таймера.
        -   Таймаут в 1 секунду у `poll` позволяет циклу периодически проверять флаг `running`, даже если таймер не сработал, обеспечивая отзывчивость к сигналам завершения.
        -   После срабатывания таймера, `read()` считывает количество "пропущенных" срабатываний (если система была сильно нагружена).
        -   В цикле вызывается переданный `functor` столько раз, сколько раз сработал таймер.

Этот модуль эффективно инкапсулирует низкоуровневую работу с системными вызовами Linux, предоставляя простой и декларативный интерфейс для периодического выполнения задач.

## Требования

-   **ОС**: Linux (из-за использования специфичных для Linux API, таких как `timerfd.h` и `pwd.h`).
-   **Компилятор**: Поддерживающий C++20 (например, GCC 12+).
-   **Система сборки**: CMake (версия 3.15 или выше).

## Зависимости

Проект использует две популярные header-only библиотеки, которые уже включены в каталог `include/`:

-   [**nlohmann/json**](https://github.com/nlohmann/json): для работы с JSON.
-   [**yhirose/cpp-httplib**](https://github.com/yhirose/cpp-httplib): для реализации HTTP-сервера и клиента.

## Сборка проекта

1.  **Клонируйте репозиторий:**
    ```bash
    git clone <адрес-вашего-репозитория>
    cd <имя-папки-репозитория>
    ```

2.  **Создайте директорию для сборки:**
    ```bash
    cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
    ```
    -   `-S .`: указывает, где находятся исходные файлы (текущая директория).
    -   `-B build`: указывает, где будет создана директория сборки (`build`).
    -   `-DCMAKE_BUILD_TYPE=Release`: собирает проект в Release-режиме (с оптимизациями).

3.  **Скомпилируйте проект:**
    ```bash
    cmake --build build
    ```

После успешной сборки исполняемые файлы будут находиться в директории `build/bin/Release/`.

### Варианты сборки

-   **Debug-сборка** (с отладочной информацией и без оптимизаций):
    ```bash
    cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
    cmake --build build
    # Исполняемые файлы будут в build/bin/Debug/
    ```

-   **Сборка с санитайзерами** (для поиска утечек памяти, неопределенного поведения и data-race-ситуаций):
    ```bash
    cmake -S . -B build -DCMAKE_BUILD_TYPE=Asan
    cmake --build build
    # Исполняемые файлы будут в build/bin/Asan/
    ```

    ```bash
    cmake -S . -B build -DCMAKE_BUILD_TYPE=Tsan
    cmake --build build
    # Исполняемые файлы будут в build/bin/Tsan/
    ```

## Разработка в Dev Container (VS Code)

Для обеспечения единообразного и изолированного окружения разработки проект поддерживает [Visual Studio Code Dev Containers](https://code.visualstudio.com/docs/remote/containers). Это позволяет любому разработчику с установленным Docker и VS Code начать работу над проектом без необходимости вручную устанавливать компиляторы, CMake или другие зависимости на свою локальную машину.

### Требования

-   [Visual Studio Code](https://code.visualstudio.com/)
-   [Docker Desktop](https://www.docker.com/products/docker-desktop/) или Docker Engine/CLI.
-   Расширение [Dev Containers](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers) для VS Code.

### Что внутри контейнера?

Dev Container сконфигурирован с помощью файлов `.devcontainer/devcontainer.json` и `Dockerfile`.

#### `Dockerfile`

-   **Базовый образ**: `ubuntu:24.04` - свежий и стабильный дистрибутив Linux.
-   **Установленные пакеты**:
    -   `g++-13`: Современный компилятор C++, полностью поддерживающий стандарт C++20.
    -   `cmake`: Кросс-платформенная система сборки.
    -   `make`: Утилита для управления сборкой.
-   **Оптимизация**: Образ минималистичен и очищается от кешей `apt` для уменьшения размера.
-   **Рабочая директория**: По умолчанию установлена в `/workspace`.

#### `devcontainer.json`

-   **Имя контейнера**: `lapin_kvadraOS_team4_test Dev Container`.
-   **Сборка**: Указывает на использование `Dockerfile`.
-   **Расширения VS Code**: При запуске контейнера автоматически устанавливаются следующие расширения для комфортной разработки на C++:
    -   `ms-vscode.cpptools`: Официальное расширение C/C++ от Microsoft (IntelliSense, отладка).
    -   `ms-vscode.cmake-tools`: Интеграция с CMake (управление сборкой, запуск, отладка).
    -   `twxs.cmake`: Подсветка синтаксиса для файлов CMake.
-   **Монтирование томов (Mounts)**:
    1.  `source=${localWorkspaceFolder},target=/workspace,type=bind`:
        -   **Что делает**: "Пробрасывает" папку с проектом с локальной машины внутрь контейнера в директорию `/workspace`.
        -   **Зачем это нужно**: Возможность редактировать файлы на локальной машине с помощью VS Code, а все изменения будут мгновенно отражаться внутри контейнера, где и будет происходить компиляция и запуск.
    2.  `source=${env:HOME},target=/host_home,type=bind,readonly`:
        -   **Что делает**: Монтирует вашу директорию с локальной машины в `/host_home` внутри контейнера в режиме "только для чтения" (`readonly`).
        -   **Зачем это нужно**: Это позволяет сканеру (`scaner` и `scaner_server`) получить доступ к файлам вашей домашней директории для их анализа, при этом защищая их от случайного изменения из контейнера.
-   **Рабочая директория**: `/workspace` (соответствует точке монтирования проекта).
-   **Пользователь**: `root`. Работа от имени `root` упрощает установку дополнительных пакетов внутри контейнера при необходимости.


## Использование

Все утилиты поддерживают общие флаги для настройки сканирования.

### Общие флаги

| Флаг                  | Описание                                                            | По умолчанию |
| --------------------- | ------------------------------------------------------------------- | ------------ |
| `-t, --time <сек>`      | Установить интервал сканирования в секундах.                        | `5`          |
| `-r, --recursive`     | Включить рекурсивный обход поддиректорий.                           | Включен      |
| `-R, --no-recursive`  | Отключить рекурсивный обход.                                        | -            |
| `-f, --full-path`     | Использовать полные (абсолютные) пути к файлам.                     | Выключен     |
| `-F, --relative-path` | Использовать относительные пути (относительно домашней директории). | Включен      |
| `-h, --help`          | Показать справку.                                                   | -            |

### Примеры запуска

#### `scaner`

Запустить сканирование каждые 30 секунд с рекурсивным обходом и полными путями:
```bash
./build/bin/Release/scaner -t 30 -f
```
Нажмите `Ctrl+C` для остановки. Результаты будут в файле `~/.media_files`.

#### `scaner_server`

Запустить сервер, который будет обновлять данные каждые 10 минут (600 секунд) без рекурсии:
```bash
./build/bin/Release/scaner_server -t 600 -R
```
Сервер будет работать в фоновом режиме. Нажмите `Ctrl+C` для остановки.

#### `scaner_client`

Для запроса данных у запущенного сервера:
```bash
./build/bin/Release/scaner_client
```
В консоль будет выведен JSON с результатами сканирования.
